# 🐠 Золотая рыбка

> ИИ-ассистент, который превращает желание в план из шагов и доводит дело до конца.
> Не «ещё один ChatGPT», а спокойный помощник с характером Золотой Рыбки.

**Невод → желание → исполнение.**

Проект **полностью бесплатный и безлимитный**: ни тарифов, ни paywall, ни рекламы,
ни счётчика «осталось 2 желания». Регистрация необязательна — гость получает всё то же самое.

## Быстрый старт

### 1. Бэкенд

```bash
python -m venv .venv
# Windows:
.venv\Scripts\activate
# macOS/Linux:
source .venv/bin/activate

pip install -r backend/requirements-dev.txt
uvicorn backend.main:app --reload --port 8000
```

- Swagger: <http://127.0.0.1:8000/api/docs>
- Health: <http://127.0.0.1:8000/api/health>

### 2. Фронтенд

```bash
npm install
cp .env.example .env      # Windows: copy .env.example .env
npm run dev               # http://localhost:5173
```

`/api` в dev-режиме проксируется на `http://127.0.0.1:8000` (см. `vite.config.ts`).

Живой предпросмотр удобно держать на отдельном порту:

```bash
npm run dev -- --host 127.0.0.1 --port 5500 --strictPort
# http://127.0.0.1:5500/
```

> **Почему не Live Server на корне проекта?**
> Корневой `index.html` подключает `/src/main.tsx` — браузер не исполняет TSX напрямую,
> поэтому получится чёрный экран. Live Server нужно настраивать на папку `dist`
> (после `npm run build`). Для разработки используйте Vite — он умеет TSX и HMR.

### 3. Проверки

```bash
npm run check          # TypeScript, оба tsconfig
npm run build          # check + production-сборка
npm run test:backend   # pytest (нужен активированный .venv)
```

### 4. Работа без ключей LLM

Сервис полностью функционален без единого ключа:

1. Если заданы `LLM_*` — пробует основной провайдер.
2. Если заданы `LLM_FALLBACK_*` — пробует бесплатный резерв.
3. Если запущена Ollama — отвечает локальная модель.
4. Иначе — офлайн-ответ: рыбка честно предупреждает и предлагает план из шагов.

Переключение никогда не выглядит как ошибка: клиент получает событие `notice`
и показывает одну спокойную строку.

## Переменные окружения

Скопируй `.env.example` в `.env`. В репозитории секретов нет.

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `VITE_API_BASE_URL` | База API для фронтенда | `/api` |
| `VITE_PROXY_TARGET` | Куда Vite проксирует `/api` в dev | `http://127.0.0.1:8000` |
| `LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL` | Основной OpenAI-совместимый провайдер | пусто |
| `LLM_FALLBACK_*` | Бесплатный резерв (OpenRouter free / Gemini) | пусто |
| `OLLAMA_BASE_URL` / `OLLAMA_MODEL` | Локальная модель | `http://127.0.0.1:11434/v1`, `qwen2.5:7b-instruct` |
| `DATABASE_URL` | PostgreSQL (Neon/Supabase) | пусто → JSON |
| `DATA_DIR` | Папка JSON-хранилища | `backend/data` |
| `CORS_ORIGINS` | Разрешённые источники через запятую | `localhost:5173` |
| `RATE_LIMIT_PER_MINUTE` | Мягкий анти-спам лимит запросов | `30` |
| `MAGIC_LINK_SECRET` | Подпись magic-link токенов | пусто |
| `PUBLIC_BASE_URL` | Публичный адрес для ссылок в письмах | `http://localhost:5173` |

> ⚠️ Всё, что начинается с `VITE_`, попадает в клиентский бандл.
> Ключи LLM — только без префикса и только на сервере.

`RATE_LIMIT_PER_MINUTE` — это защита от спама, а не продуктовый лимит:
в обычном разговоре его не видно, а количество желаний и сообщений не ограничено.

## Контракты API

Формат ошибок всегда один:

```json
{ "error": { "code": "validation_error", "message": "Проверь входные данные: ..." } }
```

| Метод | Путь | Назначение | Статус |
|---|---|---|---|
| `POST` | `/api/chat` | SSE-поток ответа рыбки | ✅ этап 2 |
| `GET` | `/api/wishes` | `{ "wishes": [...] }` | этап 3 |
| `POST` | `/api/wishes` | Создать желание `{ "title", "note?" }` | этап 3 |
| `PATCH` | `/api/wishes/{id}` | Обновить желание или шаги | этап 3 |
| `GET` | `/api/memory` | `{ "facts": [...], "updatedAt": null }` | этап 4 |
| `PUT` | `/api/memory` | Заменить снимок фактов | этап 4 |
| `POST` | `/api/auth/request` | Отправить magic link | этап 5 |
| `GET` | `/api/auth/callback?token=...` | Подтвердить вход | этап 5 |
| `GET` | `/api/health` | Живость сервиса | ✅ |

### `POST /api/chat`

Запрос:

```json
{ "sessionId": "zr-...", "message": "Хочу начать бегать", "character": "fish" }
```

Ответ — `text/event-stream`:

```text
: connected

data: {"notice":"Рыбка нырнула глубже — отвечает локальная модель"}

data: {"delta":"Слышу тебя, странник. "}

data: {"delta":"Глубокая связь сейчас недоступна..."}

data: {"done":true,"provider":"offline","usage":{}}

data: [DONE]
```

| Событие | Значение |
|---|---|
| `delta` | Очередной кусок текста ответа |
| `notice` | Провайдер сменился; показать пользователю |
| `done` | Конец ответа + фактический провайдер |
| `error` | `{ code, message }` — поток завершается |
| `[DONE]` | Технический маркер конца SSE |

История хранится на сервере по `sessionId`: клиент может перезагрузить страницу
и продолжить тот же диалог. Окно истории ограничено 24 сообщениями / 16 000 символов.

Клиент с типизированным SSE-парсером — в `src/api/client.ts`: `streamChat()`
читает поток, обрабатывает `[DONE]` и отменяется через `AbortSignal`.

## Голос

Всё работает через Web Speech API — без серверных ключей и загрузок.

| Возможность | Где | Примечание |
|---|---|---|
| Распознавание `ru-RU` | `src/hooks/useSpeech.ts` | Chrome / Edge; нужен доступ к микрофону |
| Озвучка ответов | `src/hooks/useSpeech.ts` | Голос `ru-RU`, `pitch 0.9`, `rate 0.9` |
| Кнопка «сказать» | `ChatPage` | Распознанный текст попадает в поле ввода |
| Кнопка «озвучивать» | `ChatPage` | Включает автоматическое чтение ответов |

Если браузер не поддерживает распознавание или синтез, кнопки аккуратно
отключаются с подсказкой — интерфейс не ломается.

## Дизайн-система

Токены — в `src/styles/tokens.css`, ничего не хардкодим в компонентах.

| Группа | Примеры |
|---|---|
| Море | `--scene-top`, `--scene-deep`, `--scene-mid`, `--scene-soft` |
| Золото | `--gold-100 … --gold-700`, `--stroke-gold`, `--glow-gold` |
| Бирюза | `--aqua-200`, `--aqua-400`, `--aqua-600` |
| Ошибки | `--danger-200`, `--danger-400`, `--danger-soft`, `--danger-stroke` |
| Текст | `--text`, `--text-dim`, `--text-mute` |
| Стекло | `--glass`, `--stroke`, `--shadow-card` |
| Геометрия | `--radius-sm … --radius-pill`, `--header-h`, `--safe-bottom` |

Переключение персонажа ставит `data-character="fish|kolobok"` на `<html>`:
меняются палитра сцены и аватар, интерфейс остаётся тем же.

### Анимация и производительность

- Только `transform` и `opacity` в циклах; `will-change` — точечно.
- Canvas частиц: один `requestAnimationFrame`, DPR ≤ 2, пауза при скрытой вкладке.
- Слабые устройства (`hardwareConcurrency ≤ 4`, `deviceMemory ≤ 4`, Save-Data)
  получают `data-quality="lite"`: без каустиков и Canvas-частиц, дешёвое стекло.
- `prefers-reduced-motion: reduce`: статичная сцена и мгновенные переходы.
- Анимации ставятся на паузу при `document.visibilityState === 'hidden'`.
- Никаких видеофонов и GIF.

### Мобильная компоновка чата

- До 979px сцена становится компактной: рыбка слева, заголовок и описание справа.
- Высота чата — `clamp(380px, calc(100svh - 300px), 700px)`, поле ввода
  всегда остаётся выше нижней навигации.
- На узких экранах (≤ 380px) подсказка клавиш скрывается, но поле и кнопки остаются.

## Деплой

- **Фронтенд:** Vercel / Netlify, build command `npm run build`, output `dist`.
  Для SPA нужен rewrite всех путей на `/index.html`; `/api/*` — на бэкенд.
- **Бэкенд:** Render / Fly.io, start command
  `uvicorn backend.main:app --host 0.0.0.0 --port $PORT`.
- **БД:** Neon / Supabase → `DATABASE_URL`. Без него работает JSON-файл (для одного инстанса).
- **Секреты:** только в панели хостинга, не в репозитории.
- Service worker включается в production-сборке; установка PWA требует HTTPS
  (или `localhost`).
